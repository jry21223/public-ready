# public-ready — 文案上线对账扫描

扫描网站/Web 应用中的「生硬」「技术向」「未完成」「硬编码」文案，产出一张对账表（audit table），告诉你哪些内容不适合作为「直接上线版本」。

## 四类审计

| 分类 | 含义 | 典型特征 |
|------|------|----------|
| 🔴 A 不适合直接上线 | 占位、测试、调试残留、暴露内部信息 | `TODO`、`lorem`、`测试`、`localhost`、报错堆栈直出 |
| 🟠 B 用户友好向 | 技术词外露、公文腔、甩锅式提示 | 「参数校验失败」「接口超时」「token 过期」「系统繁忙」 |
| 🟡 C 与初衷不符 | 语气/口径与产品定位矛盾、价值主张缺失 | 正式平台卖萌腔、首页只报系统名不讲价值 |
| ⚪ D 硬编码项 | 写死的、应配置化/走 i18n 的内容 | 硬编码 URL、环境名、版本号、联系方式、重复文案 |

## 使用（Agent-agnostic）

把下面两个链接发给你的 AI 工具（Claude Code、Codex、Cursor、Hermes、Trae 等任意支持 Skill 的 agent），它会自动读取并执行：

```
https://raw.githubusercontent.com/jry21223/public-ready/main/SKILL.md
https://raw.githubusercontent.com/jry21223/public-ready/main/references/stiff-copy-patterns.md
```

对 agent 说以下任何一句即可自动触发（不要求专业词）：

- 「帮我做一下**发布前准备** / 上线前检查」
- 「这个页面**能上线吗** / 可以发布了吗」
- 「文案**读起来怪怪的** / 像程序员写的 / 像没做完」
- 「帮我**检查/打磨一下文案**、提示语、报错信息」
- 「看看有没有**占位**、**写死的**、测试数据残留」

也可以手动要求 agent「读取 SKILL.md 并执行」。

默认**只出对账表、不改代码**；确认修改建议后 agent 才会动手改。开扫前 agent 会先快速探索目标，并一次性跟你对齐**范围 / 深度 / 类别 / 语气基准**——有不对的直接纠正，按确认的颗粒度开扫。

## 输出

对账表每条包含：位置（文件:行号）、原文、分类（可组合如 `A+D`）、问题、建议、优先级（🔴 上线阻塞 / 🟠 上线前应改 / 🟡 建议改 / ⚪ 可分批）。

特性：

- **报错文案三要素**：所有用户可见报错必须包含「发生了什么 + 用户能做什么」，后端透传错误不得直出
- **subagent 分派扫描**：按模块并行扫描，主 agent 只汇总，防止上下文污染影响判断
- **特征库驱动**：`references/stiff-copy-patterns.md` 提供 grep 线索与典型例句，判断有据可依
